## 一、实验目标

**把"平面上的一个点"升级为"三维空间里的一条机械臂"，同时保证只增加这一个变化。**

具体要验证：

1. MuJoCo 场景是否稳定（渲染、动力学）
2. **三维渲染的图像，模型能否利用**（从"手画的图"到"渲染的图"）
3. 三维状态和动作（2 维 → 3 维）能否学会
4. **IK 闭环控制是否可靠**（新增的控制环节）
5. 红蓝指令在三维里是否仍然起作用

## 三、环境搭建：三个实测得到的硬约束

**这一节记录的是"如果重做一遍，我希望早点知道的事"。**

### 约束 1：机械臂够程 = 0.290，方块必须放在它之内

**最初把红块放在半径 0.275、蓝块放在 0.297 —— 恰好卡在够程边界和外面**，IK 出现 0.008 ~ 0.067 的残差，而且**看症状像是 IK 算法有问题**（解出 `j3≈0`、关节角跑到 315 等离谱值）。

**实测可达半径曲线**（目标高度 z=0.175）：

```
0.04 ~ 0.28   全部可达（误差 1e-6）
0.30          误差 0.010     <- 超出够程
0.34          误差 0.050
```

**结论**：方块采样半径定为 `[0.10, 0.26]`，两端各留 0.02 余量。**400/400 场景验证可达。**

**教训**：几何参数之间是耦合的，**方块位置必须由臂长反推，不能凭感觉放**。

### 约束 2：默认光照严重不足

**MuJoCo 默认只有一盏很弱的"头灯"。** 首次渲染出来：

```
图像整体亮度     30/255
红块实际 RGB     [75, 13, 13]      <- 原始 rgba 是 (224, 36, 36)
```

**后果**：不只是"暗"，而是**橙色机械臂和暗红块混在一起** —— 模型分不清"机械臂"和"红色目标"。

**修法**：加两盏方向不同的灯。

```xml
<light pos="0.3 -0.3 1.0" dir="-0.3 0.3 -1" diffuse="0.9 0.9 0.9"/>
<light pos="-0.3 0.4 0.8" dir="0.3 -0.4 -1" diffuse="0.5 0.5 0.5"/>
```

**修完后**：红块 147~168 px、蓝柱 126~128 px、橙臂 79~140 px、绿球 23~34 px。

### 约束 3：不要用绝对阈值判断像素数

**最初用 `R > 140` 统计红块，结果全是 0** —— 因为渲染值受光照影响，和原始 rgba 不同。

**改用"相对颜色"判断**：

```python
r, g, b = a[:,:,0].astype(int), a[:,:,1].astype(int), a[:,:,2].astype(int)
n_red    = ((r > g + 30) & (r > b + 30) & (g < 90)).sum()   # R 主导，G 很低
n_orange = ((r > g + 30) & (g > b + 30) & (g > 60)).sum()   # R>G>B 但 G 不低
```

**红和橙靠 G 通道区分**（红块 G≈13，橙臂 G 中等）。

**⚠️ 但这只在光照足够时有效** —— 光照太暗时橙色也会渲染成 G 很低，被判成红色。**光照是根本，检查代码是次要。**

## 四、技术选型：为什么用 MuJoCo 而不是 PyBullet

**实测对比**（同样渲染 64×64 的无头图像）：

| | 渲染速度 | 返回格式 | 无头配置 |
|---|---|---|---|
| PyBullet TINY(CPU) | 12.7 ms/帧 = 78 帧/秒 | `(16384,)` 需 reshape | 需要 |
| PyBullet GPU(OpenGL) | 12.9 ms/帧 = 78 帧/秒 | 同上 | 需要 |
| **MuJoCo** | **0.4 ms/帧 = 2233 帧/秒** | **`(64,64,3)` 直接可用** | **零配置** |

**MuJoCo 快 28 倍，且直接返回正确格式。**

**最初担心"MuJoCo 无头渲染要配 EGL/OSMesa"—— 实测不存在，开箱即用。**

**另外**：MuJoCo 是 robosuite / LIBERO 的底层，**将来迁移成本最低**（V6 要接 LIBERO）。

**关于"MuJoCo 不内置机器人模型"**：确实只有 2 个测试模型，**但自己写 MJCF 完全可行** —— 20 行 XML 就能搭出一个带关节、能渲染的机械臂。

## 五、关键技术组件

### IK（Jacobian 迭代）

```python
重复:
    前向运动学算出末端当前位置
    误差 = 目标 - 当前
    Δ关节 = Jᵀ (J Jᵀ + λI)⁻¹ · 误差        # 阻尼最小二乘
    关节 += step × Δ关节
```

**三个要点**：

1. **`mj_forward` 必须在 `mj_jacSite` 之前** —— 否则拿到的雅可比是上一次的
2. **阻尼 `λ=1e-3` 是必须的** —— 在奇异位形附近 `pinv` 会给出巨大增量，机械臂乱甩
3. **`ik` 有副作用** —— 它会把解出的关节角写进 `data.qpos`，所以"调用完就能直接渲染"

**实测精度**：6 个测试点误差全部 1e-6，400 个随机场景 100% 可达。

### 专家策略：比例控制

```python
step = min(1.0, dist / step_size)      # 远了走满，近了收小
action = direction / dist * step
```

**"自动减速"的效果在 chunk 里能看到**：

```
第 0 步: [0.7071, 0.7071, 0.0]     走满
第 1 步: [0.7071, 0.7071, 0.0]     走满
第 2 步: [0.5858, 0.5858, 0.0]     收小了
第 3 步: [0.0, 0.0, 0.0]           已到达，不动
```

**最后一步输出全零，等于在教模型"到了就停"。**

### 动作 chunk 不需要 IK

**`expert_chunk` 是纯几何计算**（沿直线走的位移序列），描述的是**专家的意图**，不是机械臂的动力学。环境执行第一步时才用 IK。

**这样 V2.0 的模型任务和 V1 完全同构 —— 只多了 z 轴。**

## 七、训练

```
优化器   AdamW, lr=1e-3
batch    16（PairedBatchSampler 保证配对完整）
loss     base + 1.0 × pair_loss
梯度裁剪 max_norm=1.0
轮数     120（早停未触发）
```

### 曲线：又见相变，但平台期翻倍

```
epoch  1 ~ 79    平台期    tot ≈ 0.58    红蓝差异 ≈ 0.0000   <- 忽略语言
epoch  80        开始松动   红蓝差异 = 0.0033
epoch  81        相变       tot 0.5220 → 0.0640   红蓝差异 → 0.46
epoch  82 ~ 120  收敛       tot ≈ 0.007
最佳验证 loss              0.004516
```

**和 V1 是同一个现象：**

| | V1 | V2.0 |
|---|---|---|
| 平台期长度 | 37 轮 | **80 轮** |
| 相变后 loss | 0.0155 | 0.0045 |

**平台期从 37 轮变成 80 轮 —— 这是"三维更难"的量化证据。**

**而且它验证了方法的价值：难度增加了，但方法没坏（相变照样发生，结果照样好）。**

### ⚠️ 训练中途有震荡

epoch 79 和 120 出现 loss 飙升（120 时 train tot=0.1588）。**梯度裁剪压住了一部分但没有完全消除。**

**影响可控** —— 早停 + 保存最佳 checkpoint 正好处理这种情况。**最佳是 epoch 117 附近的 0.00452，没有被后面的震荡污染。**

## 九、结论

1. **三维链路完整工作** —— 从 MuJoCo 渲染到 IK 执行到闭环控制。
2. **模型和专家几乎持平**（99.5% vs 100%）—— 协变量偏移没有造成损失。
3. **模型学会了"保持在够程内"** —— 无效动作率 0.3%，和专家相同。
4. **语言在三维里仍然起作用** —— loss 低于下限 34 倍，指令打乱 +1032%。

### 无效动作率揭示的东西

**只看成功率（1.5%）看不出随机策略的问题。加上无效动作率就清楚了：**

```
随机策略的无效动作率 21.6%  —— 是模型的 72 倍
含义：随机的 [dx,dy,dz] 经常把末端推出够程，IK 解不出来，机械臂卡在边界
而模型学会了避开这些动作
```

**这是"模型知道自己的活动范围"的证据**，也是项目说明里要求这个指标的原因。

## 十、边界（这个结果不意味着什么）

| 不意味着 | 因为 |
|---|---|
| 能操作真实机器人 | 3 自由度简化臂，不是真实的 7 自由度 Franka |
| 会抓取物体 | 只做"到达上方"，没有夹爪、接触、抓起 |
| 有语言泛化能力 | 本轮语言被刻意退回固定 2 条 |
| 会关节空间控制 | 动作是"末端位置增量"，IK 由环境做 |
| 抓取成功率高 | 成功判据只是单一位置阈值，不要求连续多步满足 |
