- **日期**：2026-10-13
- **代码版本**：`f5c9c6e`

---

## 一、实验目标

验证 Mini-VLA 的**完整管线**是否工作，而不是追求任务性能。具体要回答：

1. 视觉、语言、状态三路输入能否正确进入模型并影响输出？
2. 训练能否收敛？
3. **模型是否真的在使用语言**（而不是退化成"视觉-状态→动作"策略）？
4. 闭环控制能否到达目标？

---

## 二、任务定义

```
场景：64x64 图像，一个绿色机器人、一个红色方块、一个蓝色圆
指令：「移动到红色目标」或「移动到蓝色目标」
状态：机器人当前 2D 位置 [x, y]，范围 [-1, 1]
输出：未来 4 步动作块 [4, 2]，每步 [dx, dy]，归一化到 [-1, 1]
成功：最终位置距目标 < 0.1
```

**专家动作**：朝目标方向的位移，逐分量裁剪到 `±step_size`，再除以 `step_size` 归一化。

**关键设计**：目标位置**不在状态里**（必须从图像看），场景里**有两个不同颜色的目标**（指令必须决定选哪个）。**这保证了三条输入支路都不可省略。**

## 四、关键问题：模型最初完全忽略语言

### 现象

第一次训练（未配对数据）后，消融诊断显示：

```
完整输入      0.0052
图像置零      0.8928   变化 +17082%     ← 视觉在用
指令打乱      0.0052   变化   -0%      ← 语言【完全没用】
状态置零      0.0180   变化  +247%
```

**把指令换成另一条，输出一位小数都没变。** 模型学到的是"视觉-状态→动作"策略，**不是 VLA**。

### 定位过程

逐层检查信号在哪一层消失：

| | 随机初始化 | 训练后 |
|---|---|---|
| `text_encoder` 对两条指令的输出差异 | 3.72 | **0.000004** |
| 融合入口文本 token 的尺度 | 0.345 | 0.038 |

**结论：文本编码器塌缩成了一个常量输出。** 架构本身没问题（初始化时工作正常），是训练动态把它弄没的。

### 根因：协同适应壁垒（co-adaptation barrier）

```
要用语言，需要三处【同时】改变才有收益：
    文本编码器学会区分红蓝  ┐
    融合模块学会关注文本    ├─ 缺一不可
    动作头学会利用这些信息  ┘

但单改任何一处都降不了 loss，所以梯度不推动任何一处。
结果：一个也没改。文本分支收不到梯度 → 被 weight_decay 压平 → 永久锁死。
```

**这是模仿学习里"辅助输入被忽略"的典型机制。**

---

## 五、解决方案：配对样本 + 成对差分损失

### 数据侧：配对生成

`generate_episode(..., paired=True)` 让**同一帧**产出两条样本：

```
样本 A:  图像X + 状态P + 「移动到红色目标」 → 动作标签 a_red
样本 B:  图像X + 状态P + 「移动到蓝色目标」 → 动作标签 a_blue
         └────── 完全相同 ──────┘   └─ 唯一的区别 ─┘
```

**这堵死了"靠记忆绕过语言"这条路** —— 同一输入对应两个不同的正确答案，记忆无法同时满足。

### 损失侧：成对差分

```python
base_loss = MSE(pred, target)                    # 逐条独立
pred_delta   = pred_red   - pred_blue
target_delta = target_red - target_blue
pair_loss = MSE(pred_delta, target_delta)        # 同时看两条样本
loss = base_loss + 1.0 * pair_loss
```

**原理**：`base_loss` 里没有交叉项，两条样本互不相干，所以"输出红蓝的平均方向"是个还不错的解。`pair_loss` 引入了交叉项，**要求两条样本的输出【差得对】**，平均策略从此不可行。

**忽略语言的模型：`pred_delta = 0`，而 `target_delta ≠ 0`，`pair_loss ≈ 1.7` —— 占总损失 85%，梯度被迫去读指令。**

### 数据侧配套：`PairedBatchSampler`

配对的两条样本必须待在**同一个 batch 内且相邻**（偶数位/奇数位），否则 `pred[0::2] - pred[1::2]` 会拿不相关的样本做差 —— **能算、能降、不报错，但学的是垃圾。**

`PairedBatchSampler` 按"对"打乱，对内保持相邻。

## 六、训练曲线：平台 + 相变

```
epoch   1  train=1.86989  val=1.79042
epoch  20  train=1.82707  val=1.75964
epoch  37  train=1.61723  val=1.55742   ← 卡了 37 轮，几乎没有改善
epoch  38  train=0.78248  val=0.10238   ← 【相变】突然崩下来
epoch  39  train=0.27519  val=0.06572
epoch  46  train=0.05374  val=0.02196
epoch  91  train=0.02116  val=0.01554   ← 最佳
epoch 111  早停触发（连续 20 轮未改善）
```

**前 37 轮 loss ≈ 1.6，正好是 `pair_loss` 那 1.7 的量级 —— 模型在忽略语言。**

**第 38 轮的突变是协同适应壁垒被打破的瞬间**：pair_loss 的梯度持续推着文本编码器学会区分红蓝，直到某一点它足够有用，融合立刻开始利用它，正反馈下几十轮内全部收敛。

**这个"长期平台 + 突然跃迁"在机器学习里叫 grokking。**

## 七、结果

### 损失（几乎无过拟合）

| 划分 | N | base | pair | composite |
|---|---|---|---|---|
| train | 34992 | 0.004073 | 0.007891 | 0.011964 |
| val | 4372 | 0.005488 | 0.010050 | **0.015538** |
| test | 4242 | 0.005401 | 0.010474 | **0.015875** |

**train/val/test 三者非常接近 → 泛化良好。**

### 关键基线：语言无关下限

```
任何【完全不看指令】的模型，composite loss ≥ 0.3044
本模型验证 loss = 0.015538  →  比下限低 20 倍
```

**这不是"好一点"，是跨过了一条不可逾越的线。** 只有真正使用指令才可能低于它。

### 消融（验证集）

| 破坏哪一路 | loss 变化 |
|---|---|
| 图像置零 | **+18437%** |
| **指令打乱** | **+8672%** |
| 状态置零 | +4514% |
| 红蓝输出差异 | **0.84573** |

**三路全部"不可省略"。**

### 闭环 rollout（200 场景 × 2 指令 = 400 次）

复现命令：`python -u scripts/v1/rollout.py`（`SCENE_SEED=12345`，`RANDOM_SEED=999`）

| 策略 | 红色成功率 | 蓝色成功率 | 总体 | 平均最终距离 | 平均步数 |
|---|---|---|---|---|---|
| **模型** | **100.0%** | **99.5%** | **99.8%** | 0.0582 | 7.1 |
| 专家 | 100.0% | 100.0% | 100.0% | 0.0493 | 6.9 |
| 随机 | 7.0% | 8.0% | 7.5% | 0.9643 | 47.9 |

**模型与专家几乎持平（差 1 次失败 / 400），且远超随机基线 13 倍。**

**注意红色 100% vs 蓝色 99.5% 的轻微不对称** —— 如果只报告总体 99.8%，这个信息会被掩盖。**按指令分开统计是有价值的**，虽然当前差距在统计噪声范围内（1/200）。

## 八、结论

1. **管线正确**：从数据生成到闭环控制，整条链路工作。
2. **语言确实被使用**：三条独立证据（低于理论下限 20 倍 / 消融 +8672% / 红蓝输出差异 0.85）互相印证。
3. **闭环成功**：99.8% 成功率，与专家（100%）几乎持平。
4. **协变量偏移几乎没有造成损失** —— 这超出预期。原因是专家确定性、单步误差小、任务无混沌动力学。

## 九、注意事项与已知限制

### 复现性陷阱（已在 `scripts/v1/rollout.py` 修复）

**测试场景由随机数流生成。最初场景生成和随机策略 rollout 共用同一个 `rng` —— 两者的消耗会互相影响，导致同一份模型在不同次运行中拿到不同的测试场景和不同的分数。**

**修复**：两个用途分开用独立的 rng。

```python
SCENE_SEED = 12345      # 生成测试场景
RANDOM_SEED = 999       # 随机基线的动作噪声
```

**教训**：任何"用随机数的评估"，都要问一句"这个随机流还会被谁消耗"。

### 任务的局限

| 不意味着 | 因为 |
|---|---|
| 能操作真实机器人 | 64×64 合成场景，动作仅 2 维 |
| 有通用语言理解能力 | 只有两条固定指令，文本分支实质是二分类 |
| 模仿学习总能这么成功 | 本任务动力学平凡（无接触、无摩擦、无噪声），是"最好情况" |
| 可以直接迁移到真实数据 | 真实数据是 256×256 双相机、7 自由度动作 |

### 训练不稳定性

epoch 79 / 98 / 100 出现了短暂的 loss 飙升（如 epoch 100 的 train=1.51）。原因是 `pair_loss` 梯度较大，偶尔把参数推得过远。

**影响可控**（都恢复了），而且**早停 + 保存最佳 checkpoint 正好处理了这种情况** —— 如果只看最后一个 epoch，会拿到被震荡污染的模型。
