# 实验 002：自然语言泛化（V1）

- **日期**：2026-10-14
- **权重**：`checkpoints/v1_natural_language.pt`
- **元数据**：`checkpoints/v1_natural_language.json`
- **前置**：[exp001](exp001_synthetic_reach.md)（V0，固定指令）

---

## 一、实验目标

**V0 有一个解释不了的漏洞。**

```
V0 训练用的说法：  移动到红色目标
V0 测试用的说法：  移动到红色目标     ← 一模一样
```

**所以 V0 的 99.8% 有两种解释，无法区分：**

| 解释 | 含义 |
|---|---|
| 模型理解"红色"这个含义 | ✅ 真本事 |
| 模型记住了"移动到红色目标"这串字符 | ❌ 只是查表 |

**V1 就是为了区分它们。**

**做法**：每颜色 5 条训练说法 + 3 条**永不参与训练**的测试说法。

```
SEEN:           移动到红色目标 / 走到红色目标 / 去红色目标那里 / 移动到红色的物体 / 靠近红色目标
UNSEEN_KNOWN:   红色的目标，移动到那里 / 去那里，红色的目标 / 靠近那里，红色目标   （只用见过的字）
UNSEEN_NOVEL:   请找到红色方块并过去 / 帮我去一下红色物体那里 / 红色的那个，过去   （含生字）
```

**只有 2D 任务、模型结构、动作空间全部不变** —— 唯一的变量是"指令说法"。

---

## 二、第一次尝试失败：卡在语言无关平台

**第一次训练（红蓝各自随机抽模板）卡住了：**

```
best_val = 1.620484
```

**这个数字和 V0 的平台期（1.6~1.87）完全一致** —— 模型在忽略语言（`pair_loss` 在忽略语言时约等于 1.7）。

**V0 在第 38 轮突破，V1 跑到 77+ 轮仍未突破。**

### 诊断

**当时的日志只有一个 `total`，无法判断卡住的是哪一部分。** 拆开后可以看到 `total = base + pair` 的构成 —— 而这两个分量卡住时，排查方向完全相反。

### 找到两个具体问题

**问题 1：配对样本同时引入了两个变量**

```python
# 原来的做法：红蓝各自随机抽模板
移动到红色目标  ↔  靠近蓝色目标
     ↑                    ↑
   颜色不同          句式也不同
```

**`pair_loss = MSE(pred_红 - pred_蓝, target_红 - target_蓝)` 本意是让模型学"颜色差异"，但 `pred_delta` 里混进了句式差异 —— 信噪比变差。**

**问题 2：pair_loss 的梯度尖峰**

V0 训练时出现过 loss 突然飙回 1.5 的震荡（epoch 79/98/100）。`pair_loss` 的梯度较大，偶尔把参数推得过远。

---

## 三、修复

| # | 改动 | 理由 |
|---|---|---|
| 1 | **红蓝配对用同一个模板编号** | `pair_loss` 只处理颜色差异；句式不变性交给 `base_loss` |
| 2 | **梯度裁剪 `max_norm=1.0`** | 压住 pair_loss 造成的尖峰 |
| 3 | **`compute_loss` 返回 `(total, base, pair)`** | 只看 total 无法定位问题 |
| 4 | **新增 `language_diagnostic()`** | 每 10 轮打印"红蓝输出差异"，训练中途就能看到语言通路状态 |

**关于学习率**：当时收到"降到 3e-4"的建议，**没有采纳**。

理由：模型卡住的原因是"没有梯度推动它读指令"，不是"步子太大走不稳"。**降低 LR 只会让它更慢地探索。** V0 用 `1e-3` 在第 38 轮突破 —— 同一 LR 在 V1 没突破，说明的是任务更难，不是 LR 太大。

**结果证明这个判断是对的：保持 `1e-3`，加上裁剪和配对修复后，训练成功突破。**

## 五、结论

**V1 的目标达成：模型理解的是指令含义，不是记住固定文本。**

**最有说服力的是 `UNSEEN_NOVEL`**：

```
「请找到红色方块并过去」
     ↓ tokenize（词表来自训练集）
[UNK, UNK, 到, 红, 色, UNK, UNK, UNK, UNK, 去]
     6 个 <UNK>
```

**在一半字符都是 `<UNK>` 的噪声中，模型仍然认出"红"并走了过去。**

**如果是查表，这串字符它从没训练过，必然崩掉。**

---

## 六、这个结论的边界（重要）

**100% 不等于"语言理解"。**

**模型实际学到的是**：

```
"在句子里找有没有'红'或'蓝'，然后朝对应颜色的目标走"
```

**这是理解，但是很浅的一层 —— 本质是关键词匹配。**

**没有证明的能力：**

| 未验证 | 因为 |
|---|---|
| 词序理解（"红在蓝左边"） | 任务里没有空间关系 |
| 否定（"不要去红色"） | 模板里没有否定句 |
| 多步指令 | 任务只有一步 |
| 句法结构 | 字符级 tokenizer + 极短句子 |

**这是 V1 这个难度该有的水平。** 往上属于 V4/V5（复杂自然语言）的范围。

---

## 七、待办：对照实验

**有一个无法排除的可能：测试太简单，任何模型都能过。**

**对照方案**：用**只有 1 条模板**的数据训练一遍，跑同一个评估。

| 结果 | 含义 |
|---|---|
| 仍然 100% | 测试无区分力（"找颜色字"这个策略，1 条模板就够学会） |
| 明显下降 | 测试确实在考"跨说法泛化" |

**预期**：很可能是第一种 —— 因为从 1 条模板里也能学到"找颜色字"。

**但这个对照不做，`UNSEEN` 这个指标的强度就无法确定。** 记录在此，后续需要时补做。

## 八、下一步：V2

**从 2D 到达升级到 3D 抓取。**

```
状态:  [x, y]                          ->  [x,y,z, rx,ry,rz, gripper]
动作:  [dx, dy]                        ->  [dx,dy,dz, drx,dry,drz, gripper]
任务:  走到目标                         ->  抓取红色方块 / 放入盒子
```

**保持不变**：简单 CNN 视觉编码器、字符级文本编码器、融合模块、动作头。

**目的**：先验证三维控制链路，不引入预训练模型（那是 V3 的事）。
