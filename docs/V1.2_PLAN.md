# Mini-VLA 后续升级路线

本文档保留二维任务的长期升级方向。V1.1 至 V1.3 的数据、checkpoint、闭环评测和回归测试必须保留，任何新版本都不能覆盖它们。

## 总原则

每个版本只引入一个主要难点，并在进入下一个版本前完成：

1. 环境、数据和动作接口定义；
2. 专家策略验收；
3. 数据契约和泄露检查；
4. 模型训练与消融；
5. 红蓝任务分别进行闭环评测；
6. V1 和 V1.1 回归测试。

环境、专家、数据录制、模型推理、评测和可视化保持职责分离。新版本优先通过配置增加场景因素，不在已有 V1.1 文件中散落新的魔法数字。

## V1.2：多放置区与放置区随机化

### 目标

保留 V1.1 的二维抓取流程，增加多个放置区。模型不但要选择正确的目标方块，还要把它放到指令指定的放置区。

示例指令：

```text
把红色方块放到蓝色放置区
把蓝色方块放到红色放置区
```

每个场景中放置区的位置随机生成，但放置区会在图像中清晰可见。放置区使用带边框或半透明填充的区域表示，方块使用实心几何图形表示，避免两者只靠颜色区分而发生视觉混淆。

### 为什么先用颜色标识放置区

“1 号放置区”和“2 号放置区”容易让模型记忆编号与固定位置的对应关系。使用颜色可以直接检查语言和视觉是否共同参与：

```text
红色方块 → 蓝色放置区
```

模型必须理解“方块”和“放置区”是两个不同角色，不能只学习颜色到动作的固定映射。后续如需编号，会同时随机化编号与位置，并保留视觉标志。

### 接口

首个 V1.2 版本保持 V1.1 的输入和输出维度：

```text
输入：image + instruction + [x, y, holding]
输出：action_chunk (4, 3)，每步为 [dx, dy, dgrip]
```

不新增目标位置或放置区位置的特权状态；这些信息必须从图像和指令中获得。

### 环境和数据变化

- `Scene` 增加放置区集合及其颜色/几何属性；
- 放置区位置与目标、机器人起点保持最小间距约束；
- 专家阶段变为“移动到目标 → 闭合 → 移动到指定放置区 → 打开”；
- 数据标签记录目标颜色、放置区颜色和任务字段；
- 配对样本继续保持同一观测下的相邻反事实配对；
- 失败原因增加 `WRONG_ZONE`、`ZONE_NOT_REACHED` 等结构化代码；
- 训练、验证和测试按场景划分，不能让同一场景进入多个集合。

### V1.2 验收门槛

```text
目标颜色选择正确率       >= 95%
放置区选择正确率          >= 95%
完整抓取放置成功率        >= 90%
V1.1 回归成功率           不低于现有基线
图像置零和指令打乱        明显变差
```

## V1.5：移动方块与移动放置区

V1.5 改为研究动态目标追踪与动态放置。先分别实现移动放置区、移动目标方块，再实现两者同时移动。模型推理仍只接收图像、语言和机器人状态，真实坐标和速度只用于专家轨迹、辅助标签和训练损失。第一版不同时加入静态障碍物、动态障碍物、多目标或开放域语言。详细计划见 `docs/V1.5_PLAN.md`。

## V1.6：待 V1.5c 验收后定义

V1.6 不再预先绑定移动目标任务。待 V1.5c 完成后，根据失败分布选择下一个单一主要难点，避免同时叠加动态目标、障碍物和语言泛化。

## V2.0：自然语言泛化

“任意自然语言都能理解”不能仅靠增加几个模板实现。当前字符级 tokenizer 适合有限模板，不等价于开放域语言理解。

建议分三步：

### V2.0a：模板扩展

增加“抓住/拿起/移动/搬运/放到/放置”等同义模板，并保留未见模板测试。

### V2.0b：结构化语言解析

先将自然语言解析为任务结构：

```python
{
    "object_color": "red",
    "zone_color": "blue",
    "sequence": []
}
```

解析器与视觉动作模型分离，便于单独评估语言解析错误和动作执行错误。

### V2.0c：预训练语言编码器

如果需要真正的开放域表达理解，再考虑替换或扩展当前文本编码器。此时需要单独评估语言编码器，而不能把所有错误归因于视觉动作模型。

## 版本推进顺序

```text
V1.1  单目标抓取并放置                         已完成
V1.2  多放置区 + 放置区随机化                   已完成，见 V1.2_RELEASE.md
V1.5  移动方块与移动放置区                     重新规划中
V1.6  V1.5c 验收后定义                         待定
V2.0  自然语言解析与更强语言泛化               后续
```

## 不建议同时加入的组合

以下组合会让失败归因变得困难，应拆开实现：

- 多个同色物体 + 障碍物；
- 多步任务 + 移动物体；
- 动态目标 + 开放域自然语言；
- 三维控制 + 二维任务语义升级。

每个新版本都必须能回答：失败发生在目标选择、抓取、路径、放置、任务顺序还是语言解析。
