# V1.1 升级计划：二维抓取并放置

本文档记录 V1.1 的设计、数据契约和验收约定。V1.1 已实现并通过正式闭环验收；当前正式版本见 [V1.1_RELEASE.md](V1.1_RELEASE.md)。

## 1. 升级目标

在 V1 的二维红蓝双目标任务上增加一个固定的放置区域：模型根据指令选择红色或蓝色目标，移动到目标位置，闭合二维夹爪抓住目标，将目标搬运到固定区域并释放。

任务成功必须同时满足：

1. 选择了指令指定的颜色；
2. 夹爪在目标上完成闭合；
3. 目标被夹爪携带移动；
4. 搬运到固定放置区域内；
5. 夹爪打开后目标仍留在区域内。

## 2. 明确保留和暂不加入的内容

### 保留

- 64×64 RGB 顶视二维图像；
- 一个红色目标和一个蓝色目标；
- 红蓝自然语言指令及 V1 的模板泛化评估；
- 二维机器人位置和二维闭环 rollout；
- V1 的模型主体、文本编码器和配对训练思路，除非对照实验显示必须改动。

### 暂不加入

- 三维高度或深度图；
- 机械臂关节角、腕部角和逆运动学；
- MuJoCo 或其他三维物理引擎；
- 多个同色目标；
- 随机放置区域；
- 障碍物、碰撞和遮挡；
- 多步自然语言语法；
- 真实机器人硬件控制。

## 3. 场景定义

画布仍使用 V1 的归一化二维世界坐标 `[-1,1]²`。

```text
绿色圆点：二维夹爪末端
红色圆点：红色可抓取目标
蓝色圆点：蓝色可抓取目标
黄色或灰色矩形：固定放置区域
```

### 固定参数

- 机器人初始位置：**每个物理 rollout 随机采样**，沿用 V1 的二维坐标范围和安全距离约束；训练、验证和测试使用独立随机种子；
- 红、蓝目标：继续随机采样，但不能互相重叠，也不能与起点重叠；
- 放置区域：固定中心和大小，放在两个目标采样范围之外；
- 目标半径、夹爪半径和成功容差：显式写入配置，不在脚本中散落魔法数字；
- 目标与区域的距离：足够大，使“抓到但未搬运”与“真正放置”可区分。

### 采样约束

每个场景生成后必须检查：

- 红、蓝目标都在画布内；
- 红蓝目标之间距离大于最小间隔；
- 随机机器人起点与红、蓝目标之间距离大于最小间隔；
- 目标与放置区域之间不重叠；
- 放置区域完整位于画布内。

采样失败时重新采样，并设置最大尝试次数；不能生成越界或初始重叠的训练样本。测试时不能把机器人起点固定回某个训练起点，应使用同一合法分布下的新随机起点，以验证模型是否能从不同起点完成任务。

## 4. 指令定义

V1.1 先只使用单目标单放置动作的句式，保留红蓝颜色选择：

```text
抓住红色方块并放到目标区域
把红色目标放进区域
抓取蓝色方块并放置到指定位置
把蓝色目标搬到目标区域
```

红蓝模板必须成对设计：把“红”替换成“蓝”后句式完全一致。第一阶段不加入“先……再……”等复杂语法，以免同时改变语言难度和控制难度。

## 5. 观测和动作契约

### 输入

```text
image:          (64,64,3) uint8 RGB
instruction:    str
robot_state:    [x, y, grip] float32
```

其中：

- `x,y` 是当前夹爪中心的二维世界坐标，沿用 V1 归一化约定；
- `grip` 是**实际夹持状态 `holding`**，不是上一拍的夹爪命令：`0` 表示当前没有真正夹住目标，`1` 表示目标当前被夹爪夹住并随夹爪移动；
- `holding` 只有在闭合动作执行后、目标确实位于捕获范围内时才变为 `1`；闭合命令本身不能提前把观测中的 `grip` 改成 `1`；
- 夹持状态必须是观测的一部分，否则模型无法区分“正在接近”和“已经抓住后的搬运”。

### 输出

```text
action_chunk: (4, 3) float32
每一步：[dx, dy, dgrip]
```

- `dx,dy` 延续 V1 的归一化二维位移；
- `dgrip` 由连续 `Tanh` 输出解码为三个离散命令，规则在数据录制、动作回放和闭环执行中必须完全相同：
  - `dgrip <= -0.5`：闭合；
  - `dgrip >= +0.5`：张开；
  - `-0.5 < dgrip < +0.5`：保持当前夹爪命令；
- 专家标签采用 `-1=闭合、0=保持、+1=张开`，模型可以输出连续值，但环境只能使用上述阈值后的离散命令；
- 环境执行一个 chunk 的第一步后重新观测，保持 V1 的 receding-horizon 方式；
- 夹爪动作只能改变二维开合状态，不能引入额外三维含义。

若第一版发现 `dgrip` 的连续回归不稳定，再做单变量对照：只把 `dgrip` 改成二分类，其余接口不变。不能同时改动作块长度、模型结构和场景。无论采用哪种形式，都必须保留同一套解码规则和回放测试。

## 6. 环境状态机

环境内部用明确的阶段状态机定义专家和闭环成功条件：

```text
MOVE_TO_OBJECT
  -> CLOSE
  -> MOVE_TO_ZONE
  -> OPEN
  -> DONE / FAILED
```

### MOVE_TO_OBJECT

- 夹爪保持张开；
- 专家动作指向指令指定颜色目标；
- 到达目标中心容差内后进入 `CLOSE`；
- 超过阶段最大步数则失败并记录原因。

### CLOSE

- 夹爪位置保持；
- 执行 `dgrip <= -0.5` 的闭合命令若干个 tick；
- 只有闭合命令执行完成且目标在夹爪捕获半径内时才设置 `holding=True`，下一条观测的 `grip` 才变为 `1`；
- 目标未被捕获时不能伪造成功，直接记录 `CLOSE_MISS`。

### MOVE_TO_ZONE

- 夹爪保持闭合；
- 夹爪每个 tick 只移动一小段，动作仍按 `dx,dy` 执行；
- 目标在 `holding=True` 时只跟随夹爪的**实际位移增量**：`object_next = object_now + gripper_delta`；
- 禁止把目标坐标直接赋值为放置区域中心，禁止瞬移；
- 动作指向固定放置区域中心；
- 到达区域容差内后进入 `OPEN`。

搬运过程必须是连续轨迹：从目标位置到放置区域之间至少经过多个 tick，每个 tick 的目标位移不超过该 tick 夹爪的实际位移和动作上限。记录夹爪轨迹和目标轨迹，二者在抓取后应保持相同的逐步位移；若目标轨迹出现跳变、单步位移超过上限或没有经过中间位置，数据回放测试必须失败。

### OPEN

- 执行 `dgrip >= +0.5` 的张开命令；
- 释放目标；
- 目标中心在区域内才进入 `DONE`，否则记录 `DROP_OUTSIDE`。

### 超时和失败

每个阶段设置独立最大 tick 数，并输出结构化失败原因：

```text
TARGET_NOT_REACHED
CLOSE_MISS
OBJECT_SLIPPED
ZONE_NOT_REACHED
DROP_OUTSIDE
MAX_TICKS
```

不能让失败 episode 无限循环，也不能把未抓到目标的移动误记为成功。

## 7. 专家和数据生成顺序

实现顺序必须固定，避免模型问题和数据问题混在一起：

### 第 0 步：冻结 V1

- 运行 `pytest -q`；
- 运行 V1 rollout 和语言评估；
- 保存 V1 指标作为回归基线；
- V1 文件不为 V1.1 重命名或覆盖。

### 第 1 步：只写二维环境状态机

- 新增独立的 V1.1 数据/环境模块；
- 不修改 V1 的 `synthetic.py`、V1 rollout 和 V1 checkpoint；
- 用固定动作序列测试移动、闭合、携带、释放四个阶段；
- 先不接模型。

### 第 2 步：只验证专家

对至少 **200 个随机起点场景**运行专家。为了验证真实任务，两种颜色仍然要分别执行一次完整的红色和蓝色指令，因此至少得到 400 条独立任务 episode。记录：

- 目标颜色是否正确；
- 到达目标 tick；
- 是否成功捕获；
- 搬运距离；
- 搬运 tick 数和逐 tick 的夹爪/目标位移；
- 放置后目标到区域中心距离；
- 每类失败数量。

专家必须在随机起点场景上达到 99% 以上成功率，且失败原因可解释，才能生成训练集。专家不能通过瞬移目标来达到该成功率。

### 第 3 步：录制并回放

训练数据不能把红色和蓝色录成两条独立轨迹后再交错。正确协议是：**每个随机场景只运行一条物理 rollout，在每个 timestep 对同一观测生成红、蓝两条相邻样本**。

```text
同一个 image + 同一个 robot_state + 同一个模板编号
    ├── 红色指令 -> 从当前状态去红色目标的专家动作
    └── 蓝色指令 -> 从当前状态去蓝色目标的专家动作
```

红蓝样本必须在序列中严格相邻，存储顺序固定为 `red_t, blue_t, red_{t+1}, blue_{t+1}, ...`，以兼容 V1 的 `PairedBatchSampler` 和 `prediction[0::2] - prediction[1::2]` 的 `pair_loss`。配对动作必须由同一个观测分别计算，不能从两条已经分叉的轨迹取样。

物理 rollout 可以选择一个目标颜色作为实际执行目标；配对样本是该物理状态下的反事实动作标签，不把另一条配对样本再执行一遍。具体标签规则为：

- `grip/holding == 0`：红样本指向红目标，蓝样本指向蓝目标；两者通常产生不同的 `dx,dy`；
- `grip/holding == 1`：目标已经被夹住，红、蓝样本都指向同一个固定放置区域，夹爪都保持闭合；此时两条动作可以相同，`pair_loss` 自然接近零；
- 释放后 episode 结束，不再伪造另一种颜色的后续轨迹。

这样既保留了同一观测下的反事实语言监督，又避免把两条不同输入的轨迹差异错误地当作语言差异。专家闭环验证和训练数据录制是两个不同协议：前者需要红蓝各跑一条真实任务，后者每个场景只需一条物理 rollout。

第一版数据规模固定为：

- 训练集：1000 个场景，即 1000 条物理 rollout；每个 timestep 产生 2 条配对样本；
- 验证集：200 个场景，即 200 条物理 rollout；每个 timestep 产生 2 条配对样本；
- 测试集：200 个场景，即 200 条物理 rollout；每个 timestep 产生 2 条配对样本。

数据划分以完整场景和物理 rollout 为单位，不能把同一 rollout 的帧拆到不同集合。每个集合的实际样本数由 rollout 的 tick 数决定，且必须是偶数；相邻两条样本始终属于同一观测配对，不能在配对形成后单独打乱。

每条样本保存：

```text
image, instruction, robot_state, action_chunk,
phase, target_color, object_position, zone_position,
pair_id, timestep, template_index
```

其中 `phase`、`pair_id`、`timestep` 和 `template_index` 等字段只用于诊断和配对检查，不直接喂给模型。随机抽取物理 rollout，把实际执行目标对应的动作原样回放；配对中的另一条反事实样本只用于监督，不单独执行。回放结果必须与专家一致。

### 第 4 步：数据检查

必须自动检查：

- 红蓝指令和目标颜色对应；
- 每个 `(image, robot_state, template_index, timestep)` 恰好对应相邻的红蓝样本；
- 相邻红蓝样本的图像和状态逐元素相同，只有颜色指令和目标动作标签按规则不同；
- `holding == 0` 时动作方向指向指令指定的颜色目标，`holding == 1` 时两条配对动作都指向固定放置区域；
- `grip` 始终等于环境的实际 `holding` 状态，而不是夹爪命令缓存；
- `dgrip` 按 `<= -0.5` 闭合、`>= +0.5` 张开、其余保持的规则解码；录制回放和闭环执行必须调用同一规则；
- `grip` 在移动、闭合、搬运、释放阶段符合状态机；
- 目标只在成功闭合后跟随夹爪，并且跟随的是每个 tick 的实际位移增量；
- 搬运轨迹包含多个中间状态，目标轨迹没有瞬移或不连续跳变；
- 动作值、状态值、图像形状和 dtype 符合契约；
- train/val/test 按**场景/物理 rollout**划分，不能把同一 rollout 的相邻帧或同一配对的两条样本拆到不同集合；
- 训练集和验证集都包含红、蓝目标以及各阶段。

### 开训前状态泄露检查

在启动模型训练前，使用**场景/物理 rollout 级别**的 train/validation 划分，训练一个只看 `robot_state=[x,y,grip]` 的 kNN 基线。这个检查只使用 `MOVE_TO_OBJECT` 阶段的帧，并且只保留二维移动动作幅度 `||[dx,dy]||₂ > 0.1` 的帧；不能把 `MOVE_TO_ZONE` 纳入统计，也不能把已经停在目标附近的近零动作纳入统计。对保留帧，将专家 `[dx,dy]` 归一化为移动方向，报告验证集的方向角误差和 `R²`。

第一批数据阶段，`R²=0.90` 只作为风险提示，**不是硬性拦截门槛**：

- 记录状态到方向的 kNN `R²`、方向角误差和对应数据版本；
- 若 `R² > 0.90`，标记为“可能仍有状态泄露”，优先复查随机起点、场景划分和帧筛选；
- 同时训练一个使用图像的基线，并做图像置零消融；只有当高 kNN `R²` 与“图像置零几乎无影响”同时出现时，才判定数据不可用于训练并回到采样设计；
- 在至少两到三批独立数据上同时积累 kNN 指标和图像消融结果后，再确定是否需要正式阈值及其数值。

训练完成后仍必须做图像置零消融：如果图像置零几乎不改变闭环结果或动作误差，说明视觉通路仍未被使用，不能把训练 loss 下降当成成功。

### 第 5 步：训练最小改动模型

- 先将 V1 状态编码从 2 维扩为 3 维；
- 先将动作头从 `(4,2)` 扩为 `(4,3)`；
- 视觉编码器、文本编码器、融合层、配对采样和优化器保持不变；
- 数据加载必须保持 `red_t, blue_t` 的相邻顺序；不能在形成配对后对单条样本做独立 shuffle，也不能用不识别 `pair_id` 的批采样器替代 `PairedBatchSampler`；
- 只在模型无法拟合经过验证的数据时，才进行结构升级；
- 保存 V1.1 独立 checkpoint 和训练配置，不能覆盖 `v1_natural_language.pt`。

### 第 6 步：分层评测

按以下顺序运行：

1. 专家闭环；
2. 训练集动作拟合；
3. 验证集逐阶段动作误差；
4. 红蓝指令颜色选择；
5. 目标捕获率；
6. 搬运到区域率；
7. 完整抓取放置成功率；
8. 图像、指令、状态三路消融；
9. 固定场景和固定种子复测。

## 8. V1.1 验收门槛

### 专家门槛

- 200 个验证场景（红、蓝各执行一条任务，共 400 条 episode）成功率 ≥ 99%；
- `CLOSE_MISS`、`DROP_OUTSIDE` 和超时均可单独统计；
- 动作回放与专家结果一致。

### 模型门槛

首个可接受版本建议满足：

| 指标 | 门槛 |
|---|---:|
| 红色指令完整成功率 | ≥ 85% |
| 蓝色指令完整成功率 | ≥ 85% |
| 两种颜色总体成功率 | ≥ 85% |
| 颜色选择正确率 | ≥ 95% |
| 已捕获样本的搬运成功率 | ≥ 90% |
| 随机策略成功率 | 显著低于模型 |
| V1 回归测试 | 100% 通过 |

如果模型失败，先按阶段定位：

- 目标到达低：查图像、语言和位移动作；
- 捕获低：查 `grip` 观测和闭合标签；
- 搬运低：查 `holding` 状态和携带逻辑；
- 释放低：查放置区域判定和 `dgrip` 标签。

## 9. 实验记录要求

每次实验保存：

- 使用的代码 commit；
- 随机种子；
- 场景参数；
- train/val/test episode 数；
- 专家成功率；
- 模型 checkpoint 和最佳验证 loss；
- 分阶段失败构成；
- 完整闭环成功率；
- 与 V1 的回归结果。

结论必须区分“专家失败、数据回放失败、模型动作拟合失败、闭环执行失败”，不能只报告一个总成功率。

## 10. 何时可以开始实现

只有在以下条件都满足后才开始写 V1.1 代码：

- V1 测试通过；
- V1 代码和 checkpoint 已保留；
- 放置区域、夹爪状态和动作语义已冻结；
- 专家状态机和失败原因已确定；
- V1.1 的数据契约已写入测试清单。

V1.1 已按本计划实现。后续版本必须保留 V1 回归测试和 V1.1 闭环指标作为基线。
