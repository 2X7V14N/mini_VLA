# V2.0 计划：Qwen 语言编码器的端到端 VLA

## 决策

V2.0 直接承接最终 `checkpoints/v1.5e.pt`，优先升级语言模块；V1.6 的障碍物
路线暂缓。目标不是让大语言模型直接输出机器人动作，而是让预训练语言模型理解
更自然、更长、更丰富的中文指令，再通过可训练适配器与已有视觉、状态和动作
策略融合。这仍是端到端 VLA：推理输入为图像历史、自然语言、机器人状态，输出
连续动作；不把专家坐标、颜色标签或规则解析结果作为推理输入。

## 模型选择

首个受硬件约束的实现采用：

```text
Qwen/Qwen2.5-0.5B-Instruct
```

原因：RTX 3050 Ti Laptop GPU 只有 4 GB 显存。V2.0a 冻结 Qwen 主干，以
FP16 推理语言 token；训练仅更新其 128 维投影适配器、颜色角色头和 Mini-VLA
融合/动作侧少量层。Qwen-1.5B 及以上模型不作为首个本地训练目标，除非后续
更换显存更大的硬件或加入可验证的 4-bit/LoRA 支持。

## V2.0a 架构

```text
中文指令
  -> Qwen tokenizer
  -> 冻结 Qwen 0.5B（token features）
  -> 可训练 896 -> 128 language adapter
  -> 原有多模态 Fusion <--- 4 帧视觉 token + robot state
  -> 原有 ActionHead
  -> [dx, dy, dgrip] x 4
```

Qwen 输出的 pooled language feature 还连接两个可训练角色分类头，分别预测：

- 要抓取的方块颜色：红 / 蓝 / 黄；
- 要到达的放置区颜色：红 / 蓝 / 黄。

颜色标签只用于训练的辅助交叉熵，不作为推理输入。角色 embedding 使用预测的
soft probability 加权，因此动作损失也能反向优化语言角色表示。

## 权重迁移

从 V1.5e 迁移：视觉编码器、4 帧 GRU、状态编码器、多模态 fusion、动作头、
动态位置/速度辅助头和原有颜色 role embedding。

不迁移：字符 tokenizer、字符 TextEncoder、旧的字符位置编码和字符语言摘要层。
它们由 Qwen tokenizer、冻结 Qwen 和新的 language adapter 替换。

迁移分两步进行：

1. **语言对齐阶段**：冻结视觉时序、状态和动作路径，只训练 Qwen adapter、
   角色头、角色 embedding 与融合末端；先确认不同指令可以稳定预测两种颜色角色。
2. **动作适配阶段**：以很低学习率解冻 fusion / action head，保住 V1.5e 的
   动态抓取放置能力，同时让新语言表达对应正确动作。

Qwen 主干在 V2.0a 始终冻结，不做全参数微调，也不需要 LoRA。

## 语言数据

现有 V1.5c 的三条短模板不足以证明预训练语言模型的价值。V2.0a 不改变场景、
图像、动作或 train/val/test 场景划分，只将每个 `(block_color, zone_color)` 映射
为多样中文表达，并保存显式训练标签。

- train：约 24 个语义等价模板，包含不同语序、同义词、礼貌语、补充短语；
- val：6 个未参与训练的模板；
- test：12 个未参与训练和验证的模板；
- 所有模板必须明确且只包含一个源方块颜色和一个目标放置区颜色；
- 加入“不要碰其他颜色方块”“将目标送入对应区域”等无关但自然的上下文，
  验证 Qwen 是否能保留任务角色；
- 不出现障碍物、坐标、速度或规划提示，避免和后续 V1.6 问题混淆。

评测同时报告：

1. 原 V1.5c canonical 指令上的动态控制回归；
2. V2.0 未见表达上的角色准确率与 1,800 条闭环成功率；
3. 图像置零、指令打乱、方块角色打乱、放置区角色打乱消融。

## 损失

```text
L = L_action
  + 0.05 L_block_role
  + 0.05 L_zone_role
  + 0.05 L_block_position
  + 0.02 L_block_velocity
  + 0.10 L_zone_position
  + 0.08 L_zone_velocity
  + 0.12 L_future_zone
```

动作与动态辅助目标沿用 V1.5e。两个角色损失均为交叉熵。日志必须分别打印
角色 top-1 准确率，不能只以总 loss 判断语言能力。

## 运行与验收

训练前需完成：

1. 确认本机 `transformers` 可用，并下载/缓存指定 Qwen 权重；
2. Qwen tokenizer、冻结主干、adapter、角色头的单元测试；
3. V1.5e -> V2.0 权重迁移与一批 GPU 前向预检；
4. 语言模板的颜色角色静态审计；
5. 显存基准：batch 不能触发 OOM，必要时降低 batch 或增大梯度累积。

V2.0a 验收门槛：

- 未见语言模板上 source/destination 角色准确率均至少 98%；
- canonical 指令闭环成功率不低于 V1.5e 的 79.3%；
- 未见语言表达的闭环成功率至少 75%，且九种组合没有低于 65%；
- 指令打乱 / 角色打乱消融显著失败，证明语言而非视觉偶然决定任务；
- 图像置零也显著失败，证明模型没有退化为只靠语言的开环动作。

V2.0a 通过后，才评估是否用 LoRA 解冻 Qwen 的少量末层，或进入障碍物路线。
