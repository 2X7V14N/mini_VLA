# Mini-VLA 架构笔记

## 1. VLA 的输入是什么？
        输入的是三部分：
            图像 + 语言指令 + 机器人状态 → 策略 → 动作
## 2. VLA 的输出是什么？
        输出的是动作参数，包括：关节目标、末端位置变化、速度，或包含夹爪控制的向量。
## 3. 图像、语言指令、机器人状态分别提供什么信息？
        图像：场景当前是什么样。
        指令：任务目标是什么。
        机器人状态：机器人当前在什么位置、处于什么状态。
## 4. 为什么策略模型不应该直接依赖真实机器人驱动？
        因为策略回答的是“根据观测应该采取什么动作”，驱动回答的是“怎样把动作发送给某一型号的机器人”。它们变化的原因不同，也应该分开。
        举例来说，模型可以输出“末端向左移动一小段”。模拟器可以把它变成仿真控制命令，真实机械臂驱动则可以把它转换成具体硬件接口需要的命令。这样策略可以先在仿真中测试，之后再更换执行端，而不必把机器人型号或通信协议写进模型。
## 5. 第一版为什么使用 action chunk，而不是只预测一个动作？
        模型只预测一个动作时，需要频繁重新运行推理。action chunk 一次预测接下来一小段动作，可以减少推理频率，也让连续动作有机会共同考虑，降低控制“走一步、想一步”带来的迟滞。


## 第一步：定下数据接口
    observation.image
        RGB 图像，形状 (64, 64, 3)，类型 uint8

    observation.instruction
        文本，例如“把机械臂末端移动到红色方块位置”

    observation.robot_state
        末端的二维位置 [x, y]，两个数都归一化到 [-1, 1]，类型 float32

    action
        二维位移 [dx, dy]，类型 float32
