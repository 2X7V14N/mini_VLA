## ⏸️ V1.5（暂缓，不是取消）

**目的**：在进三维之前，先用二维把"当前组件的极限"逼出来。

**设计**（已讨论清楚，可直接实施）：

```
目标：4 个 = 2 个红色 + 2 个蓝色
指令：「移动到最近的红色目标」/「移动到最左边的蓝色目标」

模型必须做两步：
    ① 按颜色筛选（从 4 个里选出 2 个）
    ② 按关系词选择（在这 2 个里选最近的/最左的）
    任一步错 -> 任务失败
```

**为什么这个设计比"4 个颜色各异的目标"好**：

| | 颜色各异 | **2 红 + 2 蓝** |
|---|---|---|
| `「最近的」` | 4 选 1，不需要颜色 | — |
| `「红色的」` | 1 选 1，不需要计算 | — |
| `「最近的红色」` | — | **两步都要对** |
| 能测出"忽略颜色"吗 | ❌ | ✅ 会 50% 错 |
| 能测出"忽略关系词"吗 | ❌ | ✅ 会 50% 错 |

**验收标准**：

| 结果 | 含义 |
|---|---|
| 颜色指令仍 100% | 没退步 |
| 「最近的红色」> 90% | ✅ 模型真的在做组合推理 |
| ≈ 25% | ❌ 在瞎猜（4 选 1 的概率） |
| 一种关系 100%、另一种 25% | ⚠️ 过拟合到单一关系，也是重要发现 |

**采样约束**：只要求【同色目标之间】距离 > min_dist（不同色的挨近没关系，模型只需在同色里选）。这样采样成功率大幅提高。

**暂缓理由**：优先推进三维控制链路。**V1.5 的结论不影响 V2 的实施**，随时可以回来做。

## 未决的对照实验（V1 遗留）

**问题**：V1 的 `UNSEEN` 测试到底有没有区分力？

**方案**：用只有 1 条模板的数据训练一遍，跑同一个 `eval_language.py`。

| 结果 | 含义 |
|---|---|
| 仍然 100% | 测试无区分力（"找颜色字"这个策略，1 条模板就够学会） |
| 明显下降 | 测试确实在考"跨说法泛化" |

**预期**：很可能是第一种。

**影响**：改变的是"这个 100% 有多惊人"，**不改变"模型会用语言"这个结论**（消融数据独立证明了）。

## V2：三维仿真控制

**目标**：验证三维控制链路能不能工作。**不引入预训练模型**（那是 V4 的事）。

```
状态:  [x, y]              ->  [x, y, z, gripper]        4 维
动作:  [dx, dy]            ->  [dx, dy, dz, gripper]     4 维
任务:  走到目标             ->  抓取指定颜色的方块
```

**动作先做 4 维**（位置 + 夹爪），**姿态用固定的"夹爪朝下"+ IK 求解**。理由：从 2D 到 7 维动作同时引入了两个变化（空间维度、姿态控制），违反"每次只增加一个主要变化"。

**保持不变**：简单 CNN、字符级文本编码器、融合模块、动作头、配对训练、pair_loss、闭环评估。

**第一步（进行中）**：环境验证
```
① 仿真器能装上
② 能加载机械臂
③ 能无头渲染 RGB          <- 最容易出问题
④ 渲染速度 > 100 帧/秒     <- 决定能否生成几万帧训练数据
⑤ 显存够（可用约 2.7 GB）
```
